=== SUMMARY ===

Total false positives: ~2090+ / 2462 (~85%)

MAIN ANALYZER LIMITATIONS:
1. ERR_PTR vs NULL confusion (~350+ findings): Kernel uses ERR_PTR extensively;
   callers use IS_ERR(), not NULL check. Analyzer treats both as "nullable."
   Affected: __filemap_get_folio_mpol, btrfs_get_*, read_cache_*, rdma_lookup_*,
   ip_route_output_*, request_key_*, debugfs_*, many more.

2. container_of modeling (~41 findings): Pure offset computation can never
   produce NULL. Affected: bfqg_to_blkg, never-null wrappers.

3. Framework invariants (~300+ findings): Callers rely on lifecycle guarantees
   the analyzer cannot model. Affected: vb2_plane_vaddr, comedi_to_usb_*,
   nvdimm_provider_data, __nf_ct_ext_find, intel_crtc_for_pipe.

4. Idiomatic patterns (~25 findings): skb_dequeue always preceded by
   skb_queue_empty() on same queue. Analyzer doesn't recognize paired pattern.

5. Design invariants (~150+ findings): xdr_reserve_space buffer pre-sizing,
   SCTP family validation, overlayfs dentry hierarchy, HSR master port existence,
   etc. Implicit guarantees not visible in code.

6. Indirect guards (~46 findings): ttm_pool_select_type implicitly guarded,
   __genradix_ptr stream pre-allocation, btf_type_by_id verifier validation,
   etc. Semantic relationships not visible to dataflow analysis.
